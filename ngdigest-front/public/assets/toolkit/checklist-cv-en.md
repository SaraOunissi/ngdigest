# Resume review checklist — 20 points

> Run this right before sending. If three or more items fail, rework the resume,
> not the cover letter.

## Substance

- [ ] The title states a job and a level ("Angular front-end developer — 8 years"), not "Software engineer".
- [ ] The first five lines are enough to know which role I'm after.
- [ ] Every role shows at least one outcome, not just a task list.
- [ ] No "participated in", "helped with", "was involved in".
- [ ] The technologies listed match what I want to do for the next two years.
- [ ] The Angular versions listed are ones I actually shipped.
- [ ] Nothing is there purely to pass an automated filter.
- [ ] Gaps longer than six months are owned in one neutral line (leave, training, side project).
- [ ] Nothing confidential: no NDA-covered client name, no internal figure.

## Form

- [ ] One page (under 8 years) or two pages max.
- [ ] One typeface, two sizes, one accent colour.
- [ ] No 4-out-of-5-star skill bars (unverifiable, works against you).
- [ ] No photo, no age, no marital status.
- [ ] Dates use the same format throughout (MM/YYYY).
- [ ] The PDF opens correctly and the text is selectable (not an image).
- [ ] The file is named `First-Last-Role.pdf`.

## Links

- [ ] The LinkedIn link works and the profile tells the same story as the resume.
- [ ] The GitHub/portfolio link doesn't lead to an empty or three-year-dead repo.
- [ ] The email address is professional and I actually read it.
- [ ] Proofread out loud, or by someone else.
